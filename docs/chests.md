# Сундуки

Префаб: `Assets/Prefabs/Props/Cathedral/Chest.prefab`. Компонент Chest использует существующие IInteractable/IPlayerVisible, сканирование игрока, InteractionMarker и DialogService. Новый ввод или специальный координатор не нужны. Префаб не размещён в сценах этой задачей.

## Настройки

- Closed Sprite / Opened Sprite — произвольные спрайты. В префабе назначены Chest 1_0 (закрытый) и Chest 1_1 (открытый) из мультиспрайта Chest 1.png.
- Locked — исходное состояние замка. По умолчанию выключено.
- Reset Open On Scene Reload — сбрасывать открытое состояние при привязке нового экземпляра после повторной загрузки сцены (также при уничтожении и пересоздании с тем же ID). По умолчанию выключено: сундук остаётся открытым. Простое отключение/включение не сбрасывает состояние; замок и оставшееся содержимое сохраняются независимо от настройки.
- Unlock Item — ссылка на ItemDefinition из общей базы Inventory/Items. В префабе назначен BronzeKey.
- Consume Unlock Item — при успешном отпирании расходуется одна единица Unlock Item. По умолчанию выключено: универсальный ключ остаётся в инвентаре. При отсутствии Unlock Item запертый сундук не открывается.
- Content / Quantity — один вид предмета и количество. По умолчанию Potion, 1. Пустая ссылка означает пустой сундук. Предмет должен присутствовать в базе инвентаря.
- Found Dialog Key — ключ локализованной реплики, по умолчанию dialog.chest.found: «Вы нашли {0}» / «You found {0}». Параметр {0} — локализованное имя найденного предмета, {1} — количество; второй параметр можно использовать в собственной реплике, например «Вы нашли {0} × {1}».
- Empty Dialog Key — dialog.chest.empty: «Пусто» / «Empty».
- Locked Dialog Key — dialog.chest.locked: «Заперто» / «Locked».
- Chest Id — постоянный уникальный ID экземпляра сундука. Назначать на экземплярах сцены, оставлять пустым в общем префабе; скопированному экземпляру с явным ID нужно назначить другой ID.

Сообщения редактируются в Assets/Localization/GameText.json. Генерированные таблицы обновляет существующий импортёр Unity. DialogService и DialogView принимают необязательную функцию параметров; при смене языка и перезагрузке UI заново вычисляются и реплика, и имя предмета.

## Открытие

Без нужного предмета показывается сообщение о замке. Сундук не считается открытым, его спрайт и маркер не переключаются. При наличии предмета отпирание, расход одной единицы (если включён) и выдача всего содержимого выполняются при том же взаимодействии, без второго подтверждения.

Открытие происходит после успешного показа диалога. Если UI недоступен или сундук отключён во время открытия UI, изменения инвентаря не запускаются. Инвентарь проверяет расход и выдачу до изменения, учитывает совпадение ключа и содержимого и переполнение количества. Состояние сундука очищается и помечается открытым до уведомления подписчиков InventoryService.Changed. Повторное взаимодействие не выдаёт лут и не расходует ключ.

После открытия спрайт остаётся открытым до пересоздания объекта с включённым Reset Open On Scene Reload; коллайдер сохраняется, сундук продолжает быть интерактивным. Повторная реплика — «Пусто». Изначально пустой сундук также открывается и показывает «Пусто». Отключение/уничтожение закрывает только принадлежащий сундуку диалог; уже завершённое получение предметов не откатывается.

## Хранилище состояния и будущая Save/Load

ChestStateService создаётся перед сценой и живёт весь запуск игры. Каждая запись по ID содержит Locked, Opened, ContentItemId и ContentQuantity. Исходные замок и содержимое префаба/экземпляра используются только для первоначального создания записи; Reset Open On Scene Reload нового экземпляра определяет, сбрасывать ли сохранённое Opened при привязке; после возвращения в сцену состояние и оставшийся лут берутся из хранилища. Объект сцены освобождает регистрацию при уничтожении, сама запись остаётся. Одновременные экземпляры с одинаковым ID отклоняются с ошибкой в консоли.

Если Chest Id пустой, временный ID вычисляется из пути сцены и пути иерархии с именами и индексами соседей. Он подходит для возврата в неизменённую сцену и различает несколько экземпляров одного префаба. Переименование, перестановка или перенос объекта меняют такой ID при следующей загрузке. Для процедурного создания, перестроения иерархии и будущих сохранений нужны явно назначенные стабильные ID; их уникальность должна соблюдаться во всей игре.

**Обязательное требование будущей Save/Load:** сохранять и восстанавливать все записи ChestStateService вместе с инвентарём как одно согласованное состояние. Сохранять постоянный ID сундука, Locked, Opened, ContentItemId и ContentQuantity. Восстанавливать базу до привязки сундуков загружаемой сцены; загруженный лут не должен заменяться первоначальными настройками префаба. При новой игре сбрасывать хранилище вместе с инвентарём. Сейчас сохранение на диск, загрузка и отдельный сброс новой игры внутри того же запуска не реализованы; новый запуск создаёт исходные состояния.

## Статус проверки

Выполнен только просмотр исходников и назначенных ссылок. Компиляция, импорт ресурсов/локализации и поведение в Unity не подтверждены. Тесты не добавлялись и не запускались; сборки и Play Mode не запускались.

Проверить вручную: оба значения Reset Open On Scene Reload при возврате в сцену (закрытый при сбросе сундук остаётся пустым и отпертым, ключ повторно не расходуется), сохранение открытого состояния при простом отключении/включении; выдачу одной/нескольких единиц и повторное «Пусто»; отсутствие ключа; отпирание с расходом и без; одинаковый предмет в Unlock Item и Content; изначально пустой сундук; независимость двух экземпляров; маркер до/после открытия и при открытом UI; RU/EN и параметры {0}/{1}; выход и возврат в сцену; отключение и включение объекта, уничтожение при открытом диалоге; сброс при новом запуске. Дополнительно проверить повторяющийся явный ID и неизвестный базе предмет: взаимодействие должно отклоняться без выдачи/расхода.
