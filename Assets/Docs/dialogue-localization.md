# Диалоги и локализация

[К оглавлению](README.md) · [English version](en/dialogue-localization.md). Актуализировано: 2026-10-18; статический просмотр. Импорт и отображение не проверялись.

## Где находится текст

**Редактируемый источник всех игровых переводов — `Assets/Localization/GameText.json`.** Формат корня — объект с массивом `entries`:

```json
{
  "entries": [
    { "key": "dialog.example.greeting", "ru": "Привет.", "en": "Hello." }
  ]
}
```

Пример иллюстрирует структуру; он не предлагает заменить существующий файл целиком. Каждой записи нужен уникальный непустой key и непустые ru/en. Основные семейства ключей: `character.*`, `class.*`, `item.*`, `dialog.*`, `menu.*`, `party.*`, `equipment.*`; ориентироваться на фактические ключи JSON, не создавать дубликат существующей записи.

В ресурсах и коде хранится ключ, а не русский текст. Динамические параметры — `{0}`, `{1}` в одинаковом порядке для обоих языков; используется String.Format, Smart Strings у импортируемых записей отключены. Литералы фигурных скобок требуют экранирования по правилам String.Format.

## Как обновлять переводы

1. Добавить/изменить записи в GameText.json, сохранить JSON и CRLF.
2. Дождаться автоматического импорта в редакторе. `Assets/Scripts/Editor/GameLocalizationImport.cs` ставит импорт в очередь после загрузки редакторских скриптов и изменения/переноса исходного JSON; ждёт завершения компиляции/обновления и выхода из Play Mode.
3. При необходимости вызвать `Tools > Localization > Import Game Text` в режиме редактирования. Сделать это до запуска игры или сборки.
4. Импортёр валидирует весь каталог, создаёт недостающие Locale ru/en, LocalizationSettings и коллекцию GameText; добавляет ключи и обновляет значения с сохранением существующих числовых ID. Таблицы помечаются для предварительной загрузки. **Удаление записи из JSON не удаляет старую запись из таблицы:** текущий ImportTable только добавляет/обновляет. Переименование ключа требует обновить все ссылки; автоматического переноса ссылок нет.
5. Генерированные `.asset` и Addressables не править вручную. Ручные переводы только через Localization Tables будут перезаписаны следующим импортом JSON. Ошибки импорта выводятся в Console как `Game text import failed`.
6. Вручную проверить RU/EN в нужном окне и смену языка при открытом представлении. В этой задаче редактор не запускался.

`Assets/Localization/Generated` содержит LocalizationSettings, en/ru, GameText (коллекция), GameText Shared Data и GameText_en/GameText_ru. Предыдущая инструкция: [docs/localization.md](../../docs/localization.md); актуальные особенности перечислены здесь.

Чтобы добавить третий язык, недостаточно нового поля JSON: ru/en жёстко заданы в импортёре и логике выбора языка. Это потребует отдельного изменения кода, Locale, загрузки и настроек UI.

## Локализация во время игры

GameLocalization автоматически создаётся до сцены и переживает переходы. Начальный язык — русский для русской системы, английский для остальных. Выбор в настройках хранится только в текущем запуске, без PlayerPrefs. `GameLocalization.IsReady` отражает завершение подготовки; до неё Text возвращает пустую строку, новые меню и диалоги не открываются.

`GameLocalization.Text(key, arguments)` возвращает текст текущего языка; при отсутствии записи используется английский вариант; если ключа нет в обеих таблицах — `[key]` и предупреждение. После готовности и смены языка вызывается `Changed`. Представления подписываются при включении и отписываются при отключении. `Func<object[]>` в диалогах позволяет пересчитать локализованные имена/параметры при обновлении текста.

## Одно сообщение и диалоговая последовательность

| Механизм | Где задаётся | Для чего |
| --- | --- | --- |
| DialogProp | Dialog Key на объекте | Короткое сообщение окружения, необязательная смена спрайта |
| Door / Chest | Ключи реплик соответствующего компонента | Замок, использованный предмет, находка, пустой сундук |
| DialogSequence | ScriptableObject с массивом Lines | Разговор с именами говорящих, фильтрацией реплик и результатом завершения |
| DialogService | Сценовый сервис со ссылкой на DialogView | Контекст ввода, открытие, продолжение, отмена и callbacks |
| DialogView | UI Toolkit / DialogTemplate | Отображение ключа/параметров, локализация, регистрация открытого окна |

Одно сообщение: `DialogService.TryShowDialog(dialogKey, onCompleted, arguments)`. Callback обычного сообщения вызывается при закрытии и сам по себе не различает естественное завершение и принудительное скрытие. Для последовательностей есть отдельный `Action<bool>`: true только после продолжения последней доступной реплики; скрытие/отключение считается отменой.

DialogService принимает один диалог одновременно; нужны активный сервис, готовые DialogView и GameLocalization, UIService и InputContextService. Условия конкретного инициатора дополнительно могут запрещать запуск при другом открытом UI. Диалог получает временный контекст Dialog; владелец освобождает его при завершении. Продолжение — `Dialog/Continue`, сейчас E на клавиатуре и восточная кнопка геймпада. Не подменять его UI/Select.

## Как добавить разговор

1. Добавить ключи имени говорящего (`character.<id>.name`) и текста (`dialog.<topic>.<line>`) в GameText.json с обоими переводами. В тексте реплики не дублировать имя: `dialog.sequence.line` форматирует имя и реплику отдельно.
2. Создать `Create > Dialog > Sequence`; обычно сохранить в `Assets/Resources/Dialogs`. Наличие в Resources само по себе не запускает разговор; нужен инициатор со ссылкой на ресурс.
3. Заполнить Lines по порядку. Speaker Key и Text Key обязательны у каждой строки, даже у условной. Пустая последовательность либо любая некорректная строка делают ресурс невалидным целиком.
4. Указать Condition: Always, HasItem или MissingItem. Для двух последних нужна ссылка Item. Если инвентарь отсутствует/отключён, условная строка не проигрывается; это не трактуется как отсутствие предмета. Проверяется общее количество предмета, а не только свободные экземпляры.
5. Указать Start Condition: Always, PlayerInteraction или NpcApproach. Оно применяется **вместе** с условием предмета. StartMode явно передаётся при запуске и сохраняется до конца разговора; наличие introduction не означает NpcApproach автоматически.
6. Для нанимаемого NPC назначить Dialog в RecruitableNpc. Для другого инициатора вызвать `TryShowSequence(sequence, onFinished, introduction, startMode)` и владеть отменой/блокировками своего действия. Универсального компонента «любой NPC с разговором без набора» в текущем наборе нет: RecruitableNpc включает вступление в группу, а DialogProp поддерживает одно сообщение.
7. Условия проверяются перед первым показом и при переходе к следующей строке. Неподходящие строки пропускаются; если ни одна не подходит, запуск вернёт false без окна. Introduction добавляется перед основной последовательностью без копирования ресурса.
8. При отмене своего действия использовать `CancelSequence` с тем же callback-владельцем; для одиночной реплики — HideDialog с её callback. Общий HideDialog закрывает текущее окно независимо от владельца и требует соответствующего контекста использования.

Выбора ответов, графа ветвления, переходов по узлам, квестовых переменных и произвольных команд на строках нет. Текущая условность — линейный список с фильтрами по предмету и способу старта. Сюжетное действие после разговора реализуется инициатором.

## Текущий пример: Шая

`ShayaNPC.prefab`: Npc Id `shaya.introduction`, Dialog `ShayaIntroduction.asset`, Recruit `Party/Shaya.asset`. Обычное взаимодействие использует PlayerInteraction. Реплика .15 о стене имеет MissingItem для RustyKey; при наличии ключа она пропускается.

В Cathedral_North_West_Room есть LostShayaTrigger со ссылками Player, NPC, Required Item = RustyKey, Introduction = ShayaCatchUp и Search Radius = 32. Проверяется положение остановившегося ведущего внутри BoxCollider2D, а не обычная реакция OnTriggerEnter. Нужны ключ, активный свободный ненанятый NPC, отсутствие открытого UI и контекст Player.

Триггер ищет кратчайший путь по четырём направлениям до свободной соседней с ведущим клетки, учитывает препятствия, размер твёрдого коллайдера NPC и персонажей группы. На время подхода блокируются управление и меню; затем передаёт разговор в RecruitableNpc с introduction и NpcApproach. При отсутствии пути блокировки не берутся; повтор доступен после выхода из зоны и входа. Прерванный подход возвращает NPC; после передачи разговора его жизненным циклом владеет RecruitableNpc.

`ShayaCatchUp` — одна вступительная фраза. В `ShayaIntroduction` для NpcApproach пропускается .01, используются общие .02–.05, вместо обычной .06 — «А ты кто?», общие .07–.09, затем две отдельные завершающие строки вместо .10–.14. Точные тексты и ключи — в ресурсах/JSON. После успешного разговора NPC выполняет короткий подход для вступления в группу.

Ручные сценарии: обычное знакомство без RustyKey и с ним; подход по триггеру с ключом; отсутствие пути; отмена/отключение; полная группа; повторный вход в сцену после набора; смена RU/EN. Не подтверждены этой задачей.
