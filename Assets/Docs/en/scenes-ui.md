# Scenes, input, camera, and UI

[Contents](README.md) · [Русская версия](../scenes-ui.md). Updated: 2026-10-29; static file inspection.

## Assembling a scene

Gameplay scenes are listed in the [catalog](catalog.md) and `ProjectSettings/EditorBuildSettings.asset`. `Assets/Settings/Scenes/URP2DSceneTemplate.unity` is a separate template excluded from the gameplay list.

For a new scene, copy a suitable gameplay scene and configure it, accounting for copied IDs and references. Provide Player with PartyFormation, PlayerSceneEntry referencing it, an active StartingPoint for direct entry, scene-local InputContextService/UIService/DialogService, UI, and a configured camera. The UI prefab alone does not supply every scene dependency: provide InputContextService separately and compare with a working scene.

Environment uses Grid/Tilemap; tiles and palettes live in `Assets/Tiles/Room`, `Cathedral`, and `Dev`, with sprites in `Assets/Sprites`. Solid obstacles require Impassable and a non-trigger 2D collider. For a new room, check walkability, collider placement, layers, and the camera confiner. The catalog lists every prefab, including palettes.

## Transitions and spawning

StartingPoint supplies position and Facing Direction when entering a scene directly without a pending transition. Multiple active StartingPoints produce a warning and select the first in hierarchy order; a missing point produces an error without repositioning the player.

TransitionPoint is a standalone prefab, not a standard enter trigger. It subscribes to PlayerController.StepComplete and requires exact equality between the completed step position and its own position. Place it on a reachable grid cell.

| Field | Configuration |
| --- | --- |
| Id | Unique point ID within the current scene |
| Target Scene | Name or full path of an available scene in Build Settings |
| Target Id | Id of an active TransitionPoint in the destination scene |
| Facing Direction | Character facing when spawning **at this** point |
| Spawn Offset | Local spawn offset transformed with TransformPoint |
| Player | Scene-local PlayerController |
| Transition Screen | Active component implementing ISceneTransitionScreen, currently SceneRevealScreen |

To connect two rooms, create one point in each, assign their IDs and reciprocal Target Scene/Target Id values, check facing, offset, and a free spawn cell, and include the new scene in Build Settings. Reassign Player/Transition Screen instead of retaining references from another scene.

A transition blocks controls, immediately covers the scene, waits two frames for presentation, records the destination in SessionStateService, and loads the scene. PlayerSceneEntry initializes the player in the new scene. SessionStateService finds the active target TransitionPoint, uses its SpawnPosition/SpawnFacing, and clears the pending transition. A missing ID or scene mismatch logs an error; StartingPoint is not silently substituted. Duplicate IDs cause a warning and select the first point.

The service stores source/destination data and guards against concurrent transitions. Cancellation before requesting load releases controls and the screen. SceneRevealScreen implements ISceneTransitionScreen; holdDuration and fadeDuration default to 0.5/0.5 seconds, though instance values may differ.

## Camera and layers

`Assets/Prefabs/Cameras/Cameras.prefab` contains Main Camera, FollowCamera, and Camera Confiner, using Cinemachine. Check the scene's Follow target against Player and configure Confiner bounds. PartyFormation.LateUpdate moves Player to the leader, keeping the camera target stable when switching characters. Character instances are created separately.

| Index | Layer | Role |
| --- | --- | --- |
| 6 | Camera | Camera objects |
| 7 | No Collisions | Objects without gameplay collisions |
| 8 | Player | Leader body |
| 9 | Impassable | Walls and blocking prop parts |
| 10 | Interactive | Interactive-object detection |
| 11 | PartyFollower | Follower bodies |
| 12 | NPC | Solid NPC bodies |

Sorting Layers are separate: Void, Background, Mid, Foreground, Default. Character assigns sortingOrder 1 to the leader and 0 to followers. The matrix in `ProjectSettings/Physics2DSettings.asset` supports party members passing through each other and PartyFollower contacting NPC. Do not substitute seemingly similar layers without inspecting explicit masks: movement uses Impassable/NPC, and interaction uses its component's mask.

## Input

Source: `Assets/Settings/InputSystem_Actions.inputactions`. The adjacent `InputSystem_Actions.cs` is generated by Unity and must not be edited manually. Scene-local InputContextService owns input. One map is active: Player, UI, or Dialog. Acquire temporary contexts with PushContext and release them with IDisposable.Dispose. PlayerController.BlockControls separately blocks world commands and also returns a disposable handle.

| Action | Keyboard | Gamepad |
| --- | --- | --- |
| Player/Move | WASD / arrows | Left stick |
| Player/Interact | E | South button |
| Player/Open Menu | Escape | North button |
| Player/Next Character | ] | Right bumper |
| Player/Previous Character | [ | Left bumper |
| UI/Up, Down, Left, Right | WASD / arrows | D-pad; UI/Navigate also contains stick bindings |
| UI/Select | Enter / Space | South button |
| UI/Back | Backspace / Escape | East button |
| Dialog/Continue | E | East button |

The asset also retains standard UI/Point, Click, ScrollWheel, Submit, Cancel, Navigate, and other-device bindings. These do not imply mouse support in the gameplay menu: MenuPanel disables picking and standard navigation events, then handles the game's actions. Hint scheme selection follows the last handled keyboard/mouse or gamepad command; a gamepad without a keyboard/mouse affects the initial selection.

PlayerController settings in the current prefab: bufferTime = 0.5 and holdRepeatDelay = 0.2. Buffered commands and switching wait until the formation stops. Add actions through the Input Actions editor, update their consumer/contexts and, if needed, the controls screen; Unity regenerates the wrapper class.

## UI Toolkit

The main prefab is `Assets/Prefabs/UI/UI.prefab`, with MenuPanel, DialogPanel, and SceneRevealPanel as its main child panels. Views use PanelRenderer and UI reload callbacks instead of assuming a VisualElement remains valid for the whole session. UXML edits must account for code-side `Q(...name...)` lookups and required element names.

| Asset under Assets/UI Toolkit | Consumer / purpose |
| --- | --- |
| MenuTemplate.uxml, MenuSidebarTemplate.uxml | MenuPanel; frame, entries, shared navigation |
| PartyPanelTemplate.uxml, CharacterInfoCardTemplate.uxml | PartyPanelView; three member cards |
| InventoryScreenTemplate.uxml | InventoryPanelView; ordinary/key-item tabs and list |
| EquipmentScreenTemplate.uxml | EquipmentPanelView; member, slots, candidates |
| StatusScreenTemplate.uxml | StatusPanelView; member selection and stats |
| SettingsScreenTemplate.uxml | SettingsPanelView; language |
| ControlsScreenTemplate.uxml | ControlsPanelView; input hints, tabs, Continue |
| DialogTemplate.uxml | DialogView |
| SceneRevealTemplate.uxml | SceneRevealScreen |
| MenuStyles.uss | Shared styles, focus, dimensions, appearance |
| PanelSettings.asset | UI panel settings |

MenuPanel coordinates Main/Inventory/Equipment/Status/Settings/Controls. Views read PartyService/InventoryService and localization and refresh on events; the menu does not own gameplay data. UIService counts open elements and publishes Opened/Closed/OpenCountChanged, used for interaction blocking and markers.

Inventory: Select moves from tabs to the list; Back returns to tabs and then the main menu. Select does not apply Potion. Equipment has member, slot, and item selection levels; Back moves up through them. Status displays current strength/agility/intellect with number colors relative to base (white/green/red), HP/MP/experience, and damage; the effects area remains a placeholder. Settings apply language changes immediately. Controls opens automatically once per session and remains accessible from the menu.

To change UI, edit the relevant UXML/USS, update views if element names change, add translations for new labels, and check prefab references. Do not replace service data with gameplay values in templates. PNG mockups under Assets/Docs are visual references, not executable UI.

Manual checks for a new scene/screen: direct entry, transitions both ways, correct leader, chain stopping, camera and obstacles, all nested screen open/close paths, controls restored, language switching, UI reload/disabling, no duplicate subscriptions. Unity was not started for this task.

EquipmentStat0–5: HP, MP, strength, agility, intellect, damage; two rows of three, always white. GameText.json uses status.agility instead of status.speed; stat labels take only {0}. Generated tables require the normal localization import in Unity. Static source review only; Unity was not run.
