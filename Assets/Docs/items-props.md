# Предметы, экипировка и интерактивные объекты

[К оглавлению](README.md) · [English version](en/items-props.md). Актуализировано: 2026-10-21; статический просмотр.

## Предметы и база

ItemDefinition — ScriptableObject через `Create > Inventory > Item`. ItemDatabase — `Create > Inventory > Database`. Рабочая база автоматически загружается из `Assets/Resources/Inventory/Items.asset` и содержит шесть предметов:

| Ресурс | Id | Category / Type | Настройки |
| --- | --- | --- | --- |
| Potion | potion | Inventory / Consumable | Данные и описание зелья; применение эффекта не реализовано |
| LongSword | long_sword | Inventory / Equipment | Weapon, OneHanded, Attack 3 |
| Scythe | scythe | Inventory / Equipment | Weapon, TwoHanded, Attack 3; старт Дариуса |
| Spear | spear | Inventory / Equipment | Weapon, TwoHanded, Attack 2; старт Шаи |
| BronzeKey | bronze_key | KeyItem / Consumable | Ключ для назначенных замков; Consumable сам по себе не означает автоматический расход |
| RustyKey | rusty_key | KeyItem / Consumable | Условия встречи/реплик Шаи и назначенных объектов |

Для нового предмета:

1. Создать `.asset` в `Assets/Resources/Inventory` и задать уникальный непустой Id. Имя файла и Id — разные значения.
2. Добавить `item.<id>.name` и `item.<id>.description` в GameText.json. Назначить Name Key и Description (это ключ, не готовый текст).
3. Выбрать Category: Inventory или KeyItem. Для экипировки нужен Inventory, Type = Equipment, корректные Slot и Handedness; Attack используется у оружия.
4. Добавить **сам ресурс** в Items базы `Inventory/Items`. Просто сохранить его в Resources недостаточно. База отклоняет null, повторные Id, пустые ключи и некорректные сочетания перечислений.
5. Назначить предмет источнику выдачи: Chest.Content, начальный комплект персонажа или отдельная логика через InventoryService. Инвентарь изначально пуст, затем получает начальную экипировку добавляемых персонажей.

ItemDefinition.GetDescription дописывает локализованные сведения о слоте, руках и атаке. Отдельной системы эффектов предметов и модификаторов аксессуаров нет.

## Общий инвентарь и экипировка

InventoryService хранит стеки и публикует Changed. `SetQuantity(id, quantity)` задаёт общее количество; `GetQuantity` включает надетое, `GetEquippedQuantity` суммирует все слоты всех участников, `GetAvailableQuantity` вычитает надетое. Нельзя уменьшить запас ниже уже надетого. Внутренние операции обмена/выдачи проверяют все изменения до применения, включая переполнение int и совпадение расходуемого и выдаваемого предмета.

Слоты персонажа: Weapon, Artifact, Amulet, Ring1, Ring2, Trinket. У предмета один тип Ring, подходящий обоим кольцевым слотам. Надевание выполняется через PartyService.TryEquip; null снимает предмет. Использовать можно только свободный экземпляр корректного ресурса из общей базы. Снятие не создаёт новую вещь — освобождает уже учтённый экземпляр.

Двуручное оружие автоматически снимает Artifact; надевание Artifact снимает двуручное оружие. С одноручным артефакт совместим. Слот артефакта остаётся доступным. При удалении участника вещи остаются в общем инвентаре и освобождаются. Число слотов жёстко согласовано в enum, PartyMember, PartyService и UI: добавление нового типа потребует изменения кода и интерфейса.

## Общий механизм взаимодействия

CharacterInteractionsController выпускает Physics2D.Raycast перед ведущим по маске Interactive/NPC, передаёт фокус объекту с IPlayerVisible и вызывает IInteractable.TryInteract по команде. Контракты не привязаны к конкретной двери или реплике.

InteractionMarker — отдельный дочерний префаб `Assets/Prefabs/UI/InteractionMarker.prefab`. Находит ближайший родительский MonoBehaviour, реализующий оба контракта, подписывается на видимость/взаимодействие/UIService. Настраиваются спрайты до и после взаимодействия и Should Toggle. Открытый UI скрывает маркер.

Новый простой объект с репликой удобно сделать копией Closet/Cabinet/SecretDialog: назначить DialogProp.Dialog Key, Sprite Renderer, Default/Interacted Sprite и Should Toggle Back; сохранить слой/коллайдер для обнаружения, при необходимости добавить маркер. Bed и Banquette сами по себе не содержат DialogProp. DialogProp меняет внешность после успешного открытия сообщения, а не добавляет предметы. Для нового типа действия можно реализовать контракты отдельным связным компонентом.

## Двери

Код: `Assets/Scripts/Props/Door.cs`. Образцы: `Assets/Prefabs/Props/Room/Door.prefab` и `Cathedral/Door.prefab`.

| Поле | Назначение |
| --- | --- |
| Door Id | Постоянный уникальный ID конкретной двери |
| Sprite Renderer, Default Sprite, Opened Sprite | Вид двери |
| Blocker | Отдельный объект препятствия; выключается после открытия |
| Is Locked | Начальный замок |
| Reset Open On Scene Reload | При новом экземпляре сбросить только Opened; по умолчанию true |
| Unlock Item | Требуемый ItemDefinition из базы |
| Consume Unlock Item | Расходовать одну свободную единицу при отпирании |
| Show Locked Dialog, Locked Dialog Key | Показывать настроенную реплику при отсутствии ключа |
| Locked Dialog Service | Необязательный явный сервис, иначе используется текущий DialogService.Instance |
| Show Unlock Dialog, Unlock Dialog Key | Необязательное сообщение использованного предмета; ключ по умолчанию dialog.unlock.used_item |

Незапертая дверь открывается автоматически при фокусе. Запертая отпирается взаимодействием с назначенным ключом; расход выключен по умолчанию. Для сообщения использования ключа параметр имени должен локализоваться заново. Открытый UI и отключённый компонент блокируют новые действия.

DoorStateService хранит Locked/Opened между сценами. При включённом Reset Open On Scene Reload дверь после возврата закрыта, но уже отперта и откроется автоматически без повторного расхода. Отключение/включение того же компонента состояние не сбрасывает. В Cathedral_Center у Door North West есть явный ID `cathedral_center.door_north_west`; текущие ссылки на ключи и overrides экземпляров сверять по сцене, не по старой записи журнала.

## Сундуки

Код: `Assets/Scripts/Props/Chest.cs`, образец `Assets/Prefabs/Props/Cathedral/Chest.prefab`. Дополнительная подробная инструкция: [docs/chests.md](../../docs/chests.md); её историческую фразу о неразмещённом префабе не распространять на текущие сцены.

1. Разместить копию префаба, настроить Closed/Opened Sprite и коллайдер. Назначить уникальный Chest Id на экземпляре; не фиксировать общий ID в базовом префабе.
2. Content — один вид предмета из Items, Quantity — количество. Null означает пустой сундук. Базовый префаб содержит Potion ×1.
3. Для замка включить Locked, назначить Unlock Item, выбрать Consume Unlock Item. В базовом префабе ключ BronzeKey назначен, но сам Locked выключен и расход выключен.
4. Found Dialog Key по умолчанию `dialog.chest.found`: `{0}` — локализованное имя, `{1}` — количество. Empty Dialog Key — `dialog.chest.empty`, Locked Dialog Key — `dialog.chest.locked`.
5. Reset Open On Scene Reload по умолчанию false. Если включить, при возврате закроется только внешний вид; замок и опустошённое содержимое сохранятся.

Открытие выполняется после успешного показа сообщения. Отпирание, возможный расход ключа и выдача всего содержимого согласованы одной операцией; при отказе инвентаря выдачи нет. Состояние очищается до уведомления подписчиков инвентаря. Повторное взаимодействие показывает «Пусто», без нового лута/расхода; твёрдый коллайдер сундука сохраняется.

## Идентификаторы и сохранение

DoorStateService и ChestStateService отклоняют одновременно зарегистрированные объекты с одинаковым ID. Если явный ID пуст, используется путь сцены и иерархия с именами и индексами соседей. Такой ID меняется при переименовании/перестановке объектов; для устойчивого контента назначать явные ID, уникальные по всей игре. У копии экземпляра менять ID.

Сервисы хранят состояние только в памяти. Для будущего Save/Load необходимо сохранять инвентарь, экипировку, группу, сессионные отметки, двери и сундуки согласованно; записи сундука включают Locked, Opened, ContentItemId, ContentQuantity, двери — Locked/Opened. Восстанавливать состояния до привязки объектов сцены. Сейчас ни общего сохранения, ни общей команды новой игры внутри одного запуска нет; SessionStateService.ResetSession сбрасывает только свою часть состояния.
